# The grp_parse gain comes from decoding each RLE scanline straight into the
# frame buffer instead of allocating and copying a Vec per line.
#
# These microbenchmarks do NOT cover the dominant cost of a real run, which is
# DDS block decode plus PNG encode. Reference figures measured end-to-end
# against /Applications/StarCraft:
#   full SD run (868 sprites, decode + PNG)      ~0.9 s
#   HD 150 sprites --convert-to-png              ~8 s, 1.09 GB peak RSS
#   HD 300 sprites --convert-to-png             ~11 s, 1.32 GB peak RSS
# Peak RSS is per-thread decode working set (the largest sprite, ultralisk, is
# 119 MB on its own), so it tracks RAYON_NUM_THREADS rather than the number of
# sprites requested.
